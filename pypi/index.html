PyPI release path

Every szl- package is published only by a GitHub Actions workflow in its source repository through PyPI Trusted Publishing, with PEP 740 attestations on every file. These are byte-identical public copies of the governance artifacts; the source of truth is the organization's health repository (private). MIRROR.json records the source commit and the mirror time.

Artifacts
  • pypi-packages.v1.json — manifest: every pyproject in the organization classified as published, queued, hold, internal or never; versions, release tags, attested source commits.
  • release-path.md — the release contract (szl.pypi-release.v2): tag-to-version binding, environment and ruleset controls, gate checks, what a release does and does not prove.
  • canonical/publish-pypi.yml — the canonical publish workflow (SHA-pinned actions; publishes only on release: published).
  • canonical/szl_pypi_release_gate.py — the fail-closed release gate that runs before any upload.
  • canonical/gen_publish_workflow.py — generator; only the package list differs between repositories.
Verify independently

PyPI's Simple API exposes a provenance URL per file; the attestation certificate carries the source repository, the commit digest and the workflow run. The a11oy.net MEASURED RECORD reads those live and binds each release tag to its attested commit.
